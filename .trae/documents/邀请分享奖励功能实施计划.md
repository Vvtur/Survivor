# 邀请分享奖励功能实施计划

## 一、需求概述

在 `GameStartPanel` 新增按钮，打开"邀请有礼"面板（`InvitePanel`）：
- **分享按钮**：调微信 SDK 分享游戏，分享链接携带邀请者 openid（`query: from=invite&inviter=<openid>`）
- **领取按钮**：若已有好友通过分享链接**进入过游戏**，可领取 **100 金币**（仅一次）；未分享/无好友游玩时点击则给出相应提示

已确认的决策：
- 奖励：100 金币（走 `GameModel.Money`，与 Last-Write-Win 云存档兼容）
- "游玩"判定：好友点开分享卡片进入小游戏即算（冷启动 + onShow 热启动都处理）
- 只给邀请者奖励，被邀请者不发奖励
- 防刷：领取资格与领取状态全部以云端记录为准（防自邀、防重复领取）

| 面板入口 | `GameStartPanel`（`Assets/Res/Scripts/UI/GameStartPanel.cs:33`）已有 `Btn_Board` 打开排行榜的先例，新按钮照此办理 |

## 三、整体设计（数据流）

```
【被邀请方】进入游戏（冷启动/OnShow）
  → 读 query.inviter → 云函数 invite(action=track)
  → 云函数校验（inviter 非空、inviter≠自己）→ invite_events 集合 doc(被邀请者openid) 写入 {inviter, ts}
  （doc 已存在则跳过 → 一个好友只能给同一邀请者计一次）

【邀请方】打开 InvitePanel
  → 云函数 invite(action=status) → {invited: bool, claimed: bool} → 刷新按钮/文案

【邀请方】点分享
  → 云函数 invite(action=get_openid) 取 openid（缓存 Storage）
  → IWXPlatformSystem.ShareToFriend("from=invite&inviter=" + openid)
  → 本地标记 SharedClicked（仅用于文案区分，资格以云端为准）

【邀请方】点领取
  → 云函数 invite(action=claim)
     未领过 && invite_events 有 inviter==自己 的记录 → 写 invite_rewards doc(自己openid) → code:0
     已领过 → code:1；无邀请记录 → code:2
  → code:0：GameModel.Money.Value += 100（Money 的 Register 自动本地持久化+云端防抖推送）
```

微信限制说明：`shareAppMessage` 拿不到成功回调（微信设计），因此"是否分享过"客户端只能记录"点击过分享"，**真正的领取资格完全由云端 invite_events 记录决定**，不可伪造。

## 四、具体改动

### A. 新云函数 `invite`（新建 2 个文件）

**`WX/custom/cloudfunctions/invite/package.json`**（照抄 load 的，改 name/description）

**`WX/custom/cloudfunctions/invite/index.js`**：
```js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const db = cloud.database()

exports.main = async (event) => {
  const { OPENID } = cloud.getWXContext()
  const action = event.action || ''

  // 1) 取自身 openid（分享拼 query 用）
  if (action === 'get_openid') {
    return { code: 0, openid: OPENID }
  }

  // 2) 被邀请者上报：invite_events doc(被邀请者openid) 幂等写入
  if (action === 'track') {
    const inviter = (event.inviter || '').trim()
    if (!inviter) return { code: 3, msg: 'empty inviter' }      // 参数非法静默跳过
    if (inviter === OPENID) return { code: 3, msg: 'self invite' } // 防自邀
    try {
      const doc = db.collection('invite_events').doc(OPENID)
      const existed = await doc.get().catch(() => null)
      if (existed && existed.data) return { code: 0, dup: true } // 已记录过，跳过
      await doc.set({ data: { inviter, ts: Date.now() } })
      return { code: 0 }
    } catch (e) { return { code: 9, msg: e.message } }
  }

  // 3) 查询资格：是否有好友进入过 + 是否已领奖
  if (action === 'status') {
    const count = await db.collection('invite_events').where({ inviter: OPENID }).count()
    const claimed = await db.collection('invite_rewards').doc(OPENID).get().then(() => true).catch(() => false)
    return { code: 0, invited: count.total > 0, claimed }
  }

  // 4) 领奖：原子校验 + 写入 invite_rewards doc(邀请者openid)
  if (action === 'claim') {
    const claimedDoc = db.collection('invite_rewards').doc(OPENID)
    if (await claimedDoc.get().then(() => true).catch(() => false)) {
      return { code: 1, msg: 'already claimed' }
    }
    const count = await db.collection('invite_events').where({ inviter: OPENID }).count()
    if (count.total === 0) return { code: 2, msg: 'no invite record' }
    await claimedDoc.set({ data: { ts: Date.now() } })
    return { code: 0 }
  }

  return { code: 4, msg: 'unknown action' }
}
```
注意 `doc.set` 在 wx-server-sdk 里参数是 `{ data: {...} }`（与项目现有 save 云函数写法保持一致，实施时对照 `WX/custom/cloudfunctions/save/index.js` 核实）。

### C. 新文件 `Assets/Scripts/Game/Systems/InviteSystem.cs`

```csharp
public interface IInviteSystem : ISystem
{
    /// <summary>邀请分享（带 inviter=openid 的 query），完成后回调是否已具备分享点击标记</summary>
    void ShareWithInvite(System.Action onShared);
    /// <summary>查询领取资格（云端为准）</summary>
    void CheckStatus(System.Action<bool invited, bool claimed> onResult);
    /// <summary>领取奖励：云端校验通过后客户端加 100 金币</summary>
    void ClaimReward(System.Action<int code> onResult); // code:0成功 1已领 2无资格
    /// <summary>进入游戏时检测启动参数里的 inviter 并上报（静默）</summary>
    void TrackInviteFromLaunch();
}
```

`InviteSystem : AbstractSystem` 实现要点：
- **OnInit**（`#if UNITY_WEBGL && !UNITY_EDITOR`）：
  - 调云函数 `invite(action=get_openid)` 拿 openid 存 `Storage("OpenId")`（拿不到不阻塞，分享时再兜底重试）
  - 注册 `WX.OnShow` 回调；首次用 `WX.GetLaunchOptionsSync().query` 处理冷启动
- **TrackInviteFromLaunch**：query 里取 `inviter`（TryGetValue，空/缺失静默跳过）→ `invite(action=track, inviter=xxx)`，失败静默
- **ShareWithInvite**：openid 优先读 Storage 缓存，无则现调 get_openid → 调 `GetSystem<IWXPlatformSystem>().ShareToFriend($"from=invite&inviter={openid}")` → 写本地标记 `Storage("InviteSharedClicked", 1)`
- **ClaimReward**：云函数 claim；`code==0` 时 `this.GetModel<GameModel>().Money.Value += 100`（Money 的 Register 自动落本地、CloudSaveSystem 防抖推云）+ 写本地 `InviteRewardClaimed=1`；回调原样返回 code
- **CheckStatus**：云函数 status，回调解析（注意 `CallFunctionParam.data` 所有字段非 null——SDK 的 fixCallFunctionData 坑）
- 响应类照 `CloudSaveSystem` 模式定义 `[Serializable]` 类用 `JsonUtility.FromJson` 解析；编辑器下（`#else`）CheckStatus/ClaimReward 直接回调失败分支，不影响编译运行

## 五、假设与决策

1. **领取资格完全以云端为准**：本地标记（InviteSharedClicked/InviteRewardClaimed）只影响 UI 文案/按钮态，不作防刷依据；防刷靠云函数（invite_events 幂等 + invite_rewards 存在性 + 防自邀）
2. **claim 云函数校验而非客户端校验**：奖励虽是客户端发金币（避免与 Last-Write-Win 云存档冲突——既定约定），但"能否领"由云端裁决，客户端只在 code=0 时加钱
3. **openid 经由云函数获取**（get_openid action）：小游戏前端无公开 API 直接拿自身 openid，云函数 `getWXContext()` 是标准做法；缓存 Storage 避免重复调用
4. **钱包安全权衡**：客户端加金币理论上可被破解绕过，但与现有云存档体系（Last-Write-Win、客户端写 Money）风险等级一致，不引入新的信任模型
5. **编辑器环境**：所有微信调用包 `#if UNITY_WEBGL && !UNITY_EDITOR`，编辑器下面板可打开、提示文案可用、无编译错误（既定约定）
6. 环境复用 `CloudSaveSystem` 的 `EnvId = cloud1-d8gevn4facad5c770`；云函数 `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })` 与 load/save 一致
7. 奖励数值 100 金币定义为 `InviteSystem` 常量（`const int RewardMoney = 100`），后续好调
